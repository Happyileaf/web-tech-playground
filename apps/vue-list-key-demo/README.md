# vue-list-key-demo

## 1. Demo 介绍

一个「Vue 3 列表渲染 key 差异可视化实验」。页面以左右双列并排渲染**同一份数据**：

- 左区：`v-for` 使用 `:key="index"`（数组索引作 key）；
- 右区：`v-for` 使用 `:key="item.id"`（数据项的稳定唯一 id 作 key）。

两区共享同一组操作按钮（头部插入、尾部插入、随机位置插入、删除、反转、洗牌、重置），每次操作对两区数据同步生效，唯一差异只有 key 策略。每个列表项内部带有文本输入框与计数按钮两个**组件本地状态**，并通过生命周期钩子实时统计并记录两个实验区的组件挂载（mounted）/卸载（unmounted）数量。

## 2. 演示目标

- 直观看到 index 作 key 时，列表在头部插入、反转、洗牌后组件本地状态与数据**错位**（状态停留在原渲染位置而非跟随原数据项）。
- 直观看到稳定 id 作 key 时，本地状态始终跟随对应数据项移动，状态与数据保持一致。
- 通过日志面板的 mounted/unmounted 计数，对比两种 key 策略下 DOM 节点的新建、卸载与复用行为。

## 3. 涉及的技术知识

- **虚拟 DOM diff**：Vue 更新列表时，会依据 vnode 的 `key` 判断新旧节点是否对应同一个组件/DOM 节点，进而决定复用、移动还是销毁重建。
- **key 的作用**：key 是 vnode 的身份标识。稳定且唯一的 key 能让 diff 算法准确识别同一节点，尽可能通过移动节点完成更新，避免不必要的组件重建与状态丢失。
- **index key 陷阱**：数组索引会随插入、删除、排序而变化。用 index 作 key 时，索引位置与数据项的绑定关系在列表变动后被重新分配，导致组件（及其本地状态）被复用到“错位”的数据上；中间插入/删除时还可能引发多余的 DOM 重建。仅当列表纯静态、无本地状态且不重排时，index key 才可接受。
- **组件生命周期**：`onMounted` / `onBeforeUnmount` 可以反映组件实例（对应真实 DOM 节点）的创建与销毁；纯节点移动复用不会触发这两个钩子。
- **Fisher–Yates 洗牌**：本 Demo 的随机洗牌采用标准 Fisher–Yates 算法，保证等概率的无偏随机排列。

## 4. 环境要求

- Node.js >= 20
- pnpm（仓库根目录指定 pnpm@10.x）

## 5. 安装方式

在仓库根目录执行：

```bash
pnpm install
```

本 Demo 仅依赖 `vue`、`vite`、`@vitejs/plugin-vue` 三个 npm 包，无任何仓库内部依赖。

## 6. 启动方式

在仓库根目录执行：

```bash
pnpm --filter vue-list-key-demo dev
```

或进入本目录执行 `pnpm dev`。开发服务器端口为 **3001**（即 http://localhost:3001 ）。

其他命令：

```bash
pnpm --filter vue-list-key-demo build    # 生产构建，输出到 dist/
pnpm --filter vue-list-key-demo preview  # 本地预览构建产物
```

## 7. 使用说明

建议按以下步骤实验：

1. **观察初始渲染**：页面打开后，日志面板出现一条「初始渲染」日志，两区各 mounted 4 个组件，累计挂载均为 4。
2. **制造本地状态标记**：在左区（index key）**第二项**的输入框中输入标记文本（如 `LEFT-MARK`），并点几次计数按钮；在右区（id key）对应数据项做同样操作（如 `RIGHT-MARK`）。
3. **头部插入**：点击「头部插入」。
   - 左区：标记文本停留在“第二个渲染位置”的组件上，但该位置现在展示的是原第一项的数据 —— **状态与数据错位**；同时左区会新建一个组件（mounted +1）。
   - 右区：标记文本跟随原数据项下移到第三项，状态与数据始终一致；右区同样只新建一个组件，其余节点通过移动复用。
4. **反转 / 洗牌**：点击「反转顺序」或「随机洗牌」，观察左区标记在固定渲染位置上“换人”，右区标记跟随 id 移动；日志中两区 mounted/unmounted 通常都为 0（纯节点移动复用），差异主要体现在本地状态归属上。
5. **删除**：点击任意项的「删除」按钮，两区同步移除该 id，日志各记录 1 次 unmounted。
6. **随机位置插入 / 尾部插入**：对比不同插入位置下两区的新建组件数与状态错位情况。
7. **重置**：点击「重置」，恢复初始 4 项数据、清空日志（重新生成一条重置后的初始渲染日志），所有项内输入与计数通过组件整体重建被清空。
8. 也可随时点击日志面板的「清空日志」仅清空日志，不影响列表数据。

## 8. 注意事项

- 本 Demo 为纯前端实验，不依赖任何外部服务、后端地址或账号。
- 新数据项的 id 由模块内递增计数器生成，全局唯一且不复用；点击「重置」后计数器一并重置，初始 id 固定为 1–4。
- 列表项的挂载高亮动画（蓝色闪烁）只在组件**新建挂载**时播放，节点被移动复用时不会闪烁，可借此用肉眼分辨哪边发生了 DOM 重建。
- 本目录不维护独立锁文件，统一使用仓库根目录的 `pnpm-lock.yaml`；复制本目录独立迁移后，执行 `pnpm install` 即可生成新的锁文件并运行。
